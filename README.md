# Бот записи на семинары

Ловит место в Google-таблице записи (формат как в таблице «Философия») и делает
**ровно одну запись**.

Как работает:

1. Каждую секунду перечитывает таблицу (через CSV-экспорт, который не тратит квоту API).
2. Ждёт, пока появится нужный семинар (например, «4 семинар») со свободными местами.
3. Пока таблица **только для просмотра**, каждую секунду проверяет права. Как только
   её откроют на редактирование, сразу вписывает твоё имя.
4. Место выбирает так: сначала нужный вопрос (например, 2-й), в нём первая свободная
   клетка слева направо. Если там всё занято — любой другой вопрос этого семинара
   (можно запретить).
5. Перед записью перепроверяет клетку и никогда не перетирает чужую запись.
6. После записи проверяет, что имя осталось. Если его перезатёрли, ищет другое место.
7. Как только запись подтверждена, **завершает работу**. Если ты уже записан (в том
   числе вручную), тоже завершает работу и больше ничего не пишет.

Если таблицу потом переделают или добавят новые места, бот это подхватит: он каждый
раз заново разбирает всю таблицу, а не запоминает координаты.

## Установка

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp config.example.json config.json   # и отредактируй
```

## Доступ к Google Sheets API

1. Зайди в <https://console.cloud.google.com/>, создай проект.
2. «APIs & Services» → «Enable APIs» → включи **Google Sheets API** и **Google Drive API**.
3. Дальше один из вариантов:
   - **Свой аккаунт (`"auth": "oauth"`)** — «Credentials» → «Create credentials» →
     «OAuth client ID» → тип «Desktop app». Скачай JSON и положи рядом с ботом как
     `credentials.json`. Если попросит настроить OAuth consent screen — тип «External»,
     добавь свою почту в «Test users». При первом запуске откроется браузер для входа.
   - **Сервисный аккаунт (`"auth": "service_account"`)** — «Create credentials» →
     «Service account» → «Keys» → «Add key» → JSON, сохрани как `service_account.json`.
     Почту сервисного аккаунта (`...@...iam.gserviceaccount.com`) владелец таблицы
     должен добавить как редактора.

## Настройки `config.json`

| Поле | Что это |
|---|---|
| `spreadsheet` | ссылка на таблицу или её ID |
| `worksheet` | название листа (`"Лист1"`), `null` — первый лист |
| `name` | что вписать, например `"Иванов И.И."` |
| `aliases` | как ещё тебя могут записать (фамилия маленькими буквами и т.п.), чтобы бот понял, что ты уже записан, и не записал второй раз |
| `target_seminar` | номер семинара, например `4`; `null` — первый новый семинар, которого не было при запуске |
| `preferred_questions` | какие вопросы брать в первую очередь, например `[2]` или `[2, 1]` |
| `allow_other_questions` | `true` — если нужный вопрос занят, взять любой другой; `false` — только из списка |
| `poll_seconds` | как часто проверять, по умолчанию `1` |
| `read_via` | `"csv"` (быстро, без лимитов) или `"api"` (лимит 60 чтений в минуту — ставь `poll_seconds` ≥ 1.5) |
| `row_label_pattern` | какие строки считать местами для записи (regex по колонке A), по умолчанию `"вопрос"` |

## Запуск

```bash
python bot.py --check     # проверить доступ: покажет права и какие семинары/места видит бот
python bot.py --dry-run   # следить, но ничего не писать (покажет, куда записал бы)
python bot.py             # боевой режим — оставь запущенным, пока не запишет
```

Держи бота запущенным заранее, до того как таблицу откроют: ноутбук не должен засыпать
(на macOS можно `caffeinate -i python bot.py`), а лучше запустить на сервере или VPS
в `tmux`. Сетевые сбои и ошибки Google бот переживает сам и продолжает работать.
